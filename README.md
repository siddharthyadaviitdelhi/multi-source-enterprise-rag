# Multi-Source Enterprise RAG

A learning-oriented Retrieval-Augmented Generation (RAG) application that ingests PDFs, CSV files , PPTX indexes text with FAISS, retrieves evidence, optionally reranks it, and asks a Groq-hosted LLM to answer with source IDs.

> **Status:** runnable educational prototype. Graph retrieval is a simple entity co-occurrence heuristic, not a production knowledge graph. The evaluation is a small smoke test, not a benchmark. Do not claim quality improvements without measuring them.

## Features

- Multi-source ingestion: PDF, (PPTX), CSV.
- Overlapping chunking with source metadata.
- Sentence-transformer embeddings and FAISS inner-product search over normalized vectors.
- Semantic retrieval, hybrid FAISS + BM25 with Reciprocal Rank Fusion (RRF), sentence-window retrieval, and graph-heuristic retrieval.
- Optional cross-encoder reranking.
- Groq chat completion for grounded answers, with `[S1]`-style citations linked to displayed source passages.
- Streamlit UI, sample policy CSVs, retrieval smoke evaluation, unit tests.

## Architecture

`Sources -> loaders -> chunking -> embeddings -> FAISS/BM25/graph -> optional reranker -> context + source IDs -> Groq -> answer + source passages`

The source ID citations are generated by the application: each supplied context passage receives an ID, and the prompt asks the model to cite those IDs. Always inspect the displayed passages; model-generated citations are not a guarantee of factual correctness.

## Supported sources

- **PDF:** text extraction via `pypdf`; scanned PDFs require OCR, which is not included.
- **CSV:** each row becomes a searchable record; this is appropriate for small/medium CSVs, not huge data warehouses.
- **SQLite:** reads tables in read-only mode; use only databases you trust.
- **Website:** fetches a public HTTP/HTTPS page and extracts visible text. JavaScript-heavy websites, login-protected pages, and crawling entire domains are not supported by this basic loader.

## Retrieval modes

- **semantic:** FAISS nearest-neighbor search over normalized embeddings.
- **hybrid:** merges FAISS and BM25 ranked lists using Reciprocal Rank Fusion.
- **sentence_window:** indexes sentence-sized records and restores adjacent sentences for context.
- **graph:** heuristic capitalized-entity co-occurrence links. This is deliberately a baseline; it is not a reliable general-purpose entity extractor or a production knowledge graph.
- **reranker:** optional cross-encoder scores query/passage pairs and reorders retrieved candidates. On first use it downloads model weights. If unavailable, the app continues with the original ranking and records a note in results.

## Tests and evaluation

- `pytest -q`: deterministic unit tests for chunking, sentence-window restoration, and graph helper behavior.
- `python evaluation/evaluate.py`: tiny manually authored retrieval smoke test.
- For a meaningful benchmark, create a larger held-out set of questions and gold source passages. Track Recall@k / MRR for retrieval and separately review answer correctness, groundedness, citation accuracy, latency, and cost. Compare modes under the same questions; do not assume hybrid or reranking always improves every dataset.

## Known limitations / production hardening

- The in-memory FAISS index is rebuilt when the app starts or sources are added; persistent index integration and incremental updates are not included in the UI.
- Graph extraction is heuristic and can miss entities or connect unrelated capitalized words.
- Source text is sent to the configured Groq model when generating an answer. Do not index confidential, regulated, or third-party data without authorization.
- Web loading makes an HTTP request to the provided URL. Restrict allowed domains and add SSRF protections before exposing this to untrusted users.
- Add authentication, upload limits, file validation, structured logging, caching, error monitoring, and deployment secret management before production use.
- This project does not provide access control at document level. It is a demo, not an enterprise-secure knowledge system.

## How to explain RAG in an interview

1. **Retrieval:** search for passages relevant to the user's question.
2. **Augmentation:** add the retrieved passages to the model prompt.
3. **Generation:** ask the LLM to answer from those passages.
4. **Grounding:** show the source passages and ask the model to cite source IDs. This reduces unsupported answers but does not eliminate hallucinations.

### PowerPoint support
PowerPoint `.pptx` files are parsed slide by slide. Text boxes, titles, and table cells are extracted; images, charts, and text embedded only inside screenshots are not OCR-processed. Legacy `.ppt` files are not supported; save them as `.pptx` first.
